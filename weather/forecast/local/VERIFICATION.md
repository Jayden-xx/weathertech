# 중기예보 웹사이트 검증 결과

검증일: 2026-11-07 KST. 최초 제작 때는 실제 인증키 없이 검증했습니다. 이후 사용자가 KEY.env를 설정해 네 기능의 실제 인증 응답까지 확인했습니다. **최신 상태는 아래 9번 추가 검증이 우선**하며, 1~8번은 최초 제작 당시의 검사 이력입니다.

## 1 자료 확인

원본 ZIP 내부의 Word 활용가이드와 2025.12 Excel을 읽었습니다. 원본 파일 해시와 추출 건수는 SOURCE_NOTES.json에 기록했습니다. Word 원문은 분석 자료로만 읽었고 문서의 요청 예제는 실제 최신 응답으로 취급하지 않았습니다.

| 기능 | 지역 코드 출처 | 등록 수 | 요청 |
|---|---|---:|---|
| getMidFcst | Word 지점번호표 | 10 | stnId, tmFc + 공통 요청항목 |
| getMidLandFcst | Word 육상 코드표 | 10 | regId, tmFc + 공통 요청항목 |
| getMidTa | Excel Sheet3의 특성 C | 203 | regId, tmFc + 공통 요청항목 |
| getMidSeaFcst | Word 해상 코드표 | 13 | regId, tmFc + 공통 요청항목 |

공통 요청은 serviceKey, numOfRows=10, pageNo=1, dataType=JSON입니다. 06시 +4~+10일, 18시 +5~+10일, KST와 최근 24시간 범위를 적용했습니다. 중기예보에 nx/ny/category/fcstValue 구조를 사용하지 않았습니다.

문서 차이: regid/regId 표기, 기온 예제의 Min/명세의 Low 차이를 확인했습니다. 실제 인증 응답은 아직 없어 Min을 Low로 자동 해석하지 않고 Low/High 범위도 시각화하지 않습니다. 해상 A/B는 가이드 및 공식 API허브 명세에서 최저/최고 방향을 확인했습니다.

## 6 코드 검토로만 확인한 항목

- 숨긴 탭에서 자동 갱신 중지: `document.hidden` 검사와 visibilitychange·pagehide·pageshow 처리 구현. 이 IAB 환경에서는 다른 탭을 열어도 기존 페이지의 document.hidden이 false여서 실제 숨김 전환은 재현하지 못했습니다.
- 페이지 이동 시 타이머 정리·진행 중 fetch 취소, 요청 진행 중 중복 방지 구현. 동시 외부 요청 합치기는 별도 자동 검사로 확인했지만 모든 브라우저 타이밍 조합을 재현하지 않았습니다.
- 실패 시 브라우저 재시도 간격 증가·같은 지역의 이전 정상 결과 유지 구현. 서버 측 오류·이전 캐시 유지는 모의 자동 검사로 확인했고 실제 제공기관 장애의 브라우저 상황은 재현하지 않았습니다.
- 키를 브라우저에 보내지 않는 구조, HTML textContent 표시, 정적 파일 허용 목록, 외부 오류 원문 미출력은 코드 검토. 임의의 모든 키 형태·제공기관 반사 인코딩에 대한 완전한 보증은 아님. 실제 키가 없어 실제 키 문자열로 검색하지 않았습니다.
- 일반 Windows 터미널의 Ctrl+C 종료 처리 구현. 이 작업의 PTY에서 두 번 Ctrl+C를 보냈으나 서버에 신호가 전달되지 않았습니다. 따라서 **실제 터미널 Ctrl+C 종료 검증은 미완료**입니다. 검증 서버는 소유한 프로세스를 명시적으로 정리합니다.

## 7 실제 API 확인 범위와 남은 일

키 없이 외부 HTTPS 진단 요청 1회에서 제공기관의 인증키 없음 오류를 받았습니다. 이 진단은 프로젝트 게이트웨이 바깥에서 실행했으므로 앱의 실제 외부 예보 호출량은 0입니다. TLS 연결 확인과 인증된 예보 조회 성공을 구분했습니다.

아직 확인하지 못한 사항:

1. 실제 키로 네 기능이 모두 정상 응답하는지, 활용신청 권한이 있는지
2. 실제 응답의 지역 변경·06시/18시 필드·결측 숫자 표시·응답 코드 대소문자
3. 최신 발표본의 실제 게시 지연과 실제 데이터가 없는 지역의 범위
4. 기온 Low/High와 예제 Min 표기의 정확한 산술 의미
5. 제공기관의 일일 집계 기준·정확한 초기화 시각
6. 사용자 일반 터미널의 Ctrl+C와 실제 브라우저 탭 숨김 전환

공식 일일 집계 정책을 확정하지 못해 최근 24시간 9,000회 제한을 적용했습니다. 다중 서버 분산 상태 공유는 지원하지 않으며 단일 중앙 게이트웨이 구성을 명시했습니다. 허용량 확인을 위해 실제 API를 대량 호출하지 않았습니다.

KEY.env를 설정하고 재시작한 뒤 모의 모드를 끄고 네 기능을 순서대로 확인하세요. 서로 다른 실제 API 호출은 전체 30초 이상 간격을 두어야 하며, 대기 안내가 뜨면 반복 클릭하지 말고 다음 확인을 기다리세요. 인증키를 채팅에 보내지 마세요.

## 8 배포 파일 확인

제공 ZIP은 허용 목록의 프로젝트 소스·문서·설정 예제만 포함합니다. 실제 KEY.env, 기존 비밀 설정, .runtime DB, Python 캐시, 작업용 원본 추출 파일은 포함하지 않습니다. KEY.env.example은 `KMA_SERVICE_KEY=YOUR_API_KEY`만 포함하는지 패키징 시 검사합니다. 이 프로젝트는 로컬 실행용이며 외부 호스팅에 게시하지 않았습니다.
