# Nuvv Portfolio — 제품 요구사항 문서(PRD)

> PRD는 ‘누구를 위해, 무엇을, 어떻게 만들고, 무엇을 기준으로 완성이라고 판단할지’를 설명하는 문서입니다. 이 문서는 실제 웹사이트 제작 시 기획·디자인·개발·검수의 공통 기준으로 사용합니다.

- 프로젝트 폴더명: `portfolio`
- 문서명: `prd.md`
- 작성일: 2026-10-31
- 버전: 1.0
- 현재 단계: 요구사항 정의 완료 / 사진 및 연락처 반영 전
- 프로젝트 원칙: 기존 프로젝트의 코드와 설정을 수정하지 않고 별도 폴더에서 시작합니다.

## 1. 제품 개요

### 1.1 한 문장 소개

**Nuvv의 여행과 웰니스 사진을 어두운 매거진 형식으로 소개하고, 에이전시·브랜드 담당자가 촬영 의뢰를 위해 쉽게 연락할 수 있는 개인 포트폴리오 웹사이트.**

### 1.2 만들려는 이유

방문자는 사진을 통해 Nuvv의 시선과 촬영 스타일을 빠르게 이해하고, 프로젝트를 살펴본 뒤 이메일 또는 인스타그램으로 연락할 수 있어야 합니다. 화려한 효과보다 사진 감상, 편한 탐색, 빠른 로딩을 우선합니다.

### 1.3 확정된 사항

| 항목 | 결정 내용 |
| --- | --- |
| 작가명 | Nuvv |
| 활동 분야 | Photography — Travel & Wellness |
| 핵심 방문자 | 사진작가를 찾는 에이전시·브랜드 담당자 |
| 시각적 분위기 | 어두운 배경의 감각적인 매거진 |
| 필수 콘텐츠 | 본인만 편집 가능한 자기소개, 작업물 목록 및 상세 페이지 |
| 첫 공개 작업물 | 프로젝트 4개, 프로젝트별 사진 최대 10장 |
| 자기소개 수정 | 관리자 로그인 후 전용 화면에서 편집 |
| 작업물 수정 | 사진 파일과 프로젝트 정보 파일로 관리 |
| 연락 수단 | 이메일 링크, 인스타그램 링크 |
| 기기 대응 | 모바일·태블릿·데스크톱에서 화면에 맞게 구성 변경 |
| 문구 방향 | 사진 분위기에 맞는 짧고 감각적인 영문 |

### 1.4 이번 문서에서 적용하는 기본값

- 공개 사이트의 메뉴, 소개, 프로젝트 문구는 영문을 기본으로 합니다. 관리자 화면은 운영하기 쉬운 한국어로 구성합니다.
- 자기소개는 홈 안의 About 섹션에 배치합니다. 작업물은 독립된 목록·상세 페이지로 제공합니다.
- 프로젝트 추가는 ‘폴더 복사 → 사진 넣기 → 정보 파일 수정 → 검증 → 배포’ 방식으로 설계합니다.
- 실제 사진이 아직 전달되지 않았으므로 프로젝트 제목·설명·대체 텍스트는 사진 확인 후 확정합니다.
- 공개 이메일, 인스타그램 주소, 도메인, 최종 프로젝트명은 공개 전 입력해야 할 값으로 남겨둡니다.

## 2. 사용자와 핵심 경험

### 2.1 공개 방문자

브랜드나 에이전시 담당자는 모바일로 링크를 처음 열거나, 데스크톱에서 여러 사진작가를 비교합니다. 긴 설명보다 사진의 분위기, 작업 주제, 작가 소개, 연락 방법을 빠르게 확인할 수 있어야 합니다.

**대표 이용 흐름**

1. 홈에서 대표 사진과 Nuvv의 이름을 확인합니다.
2. Selected Work를 누르거나 화면을 내려 작업을 살펴봅니다.
3. 프로젝트를 선택해 사진과 짧은 설명을 감상합니다.
4. About에서 작가의 관심 분야와 시선을 확인합니다.
5. Contact에서 이메일 또는 인스타그램을 엽니다.

### 2.2 사이트 소유자

Nuvv는 관리자 화면에서 자기소개를 수정하고, 작업물은 정해진 파일 형식으로 추가합니다. 프로젝트를 늘릴 때 페이지 코드나 레이아웃 코드를 직접 수정할 필요가 없어야 합니다.

**운영 흐름**

- 자기소개: 로그인 → 문구 수정 → 미리보기 → 저장 → 공개 화면 확인.
- 작업물: 예제 폴더 복사 → 사진 교체 → 프로젝트 정보 수정 → 검사 → 미리보기 → 배포.

## 3. 범위와 우선순위

### 3.1 첫 공개에 반드시 포함

- 사진 중심의 홈 화면과 대표 이미지.
- 프로젝트 4개를 보여주는 Work 목록.
- 프로젝트별 독립 주소와 사진 갤러리.
- 본인 인증을 거친 자기소개 편집 화면.
- 이메일·인스타그램으로 연결되는 Contact 영역.
- 화면 너비에 따라 배치와 이미지 크기가 바뀌는 반응형 화면.
- 사진 확대 보기, 키보드 조작, 절제된 화면 효과.
- 파일 기반 프로젝트 추가 구조와 초보자용 운영 안내.
- 검색·공유에 필요한 제목, 설명, 대표 이미지.

### 3.2 추후 검토

- 프로젝트 수가 많아졌을 때 Travel / Wellness 필터.
- 한글·영문 전환.
- 프로젝트까지 웹에서 편집할 수 있는 관리 화면.
- 방문 통계, 비공개 클라이언트 갤러리.

### 3.3 첫 공개 범위에서 제외

문의 양식, 예약·결제, 방문자 회원가입, 댓글, 블로그, 사진 판매 기능은 포함하지 않습니다.

## 4. 사이트 구성과 주소

| 화면 | 주소 예시 | 역할 |
| --- | --- | --- |
| Home | `/` | 작가명, 대표 사진, 선정 작업, 자기소개, 연락처 |
| Work | `/work` | 공개된 전체 프로젝트 목록 |
| Project | `/work/[slug]` | 프로젝트 설명과 사진 갤러리 |
| About | `/#about` | 홈 안의 자기소개로 바로 이동 |
| Contact | `/#contact` | 홈 안의 연락 영역으로 바로 이동 |
| 관리자 로그인 | `/admin/login` | 소유자 로그인 |
| 자기소개 편집 | `/admin/about` | 인증된 소유자만 소개 수정 |
| 없는 페이지 | 잘못된 주소 | 안내 및 Work/Home 복귀 링크 |

`slug`는 프로젝트 주소에 쓰는 짧은 영문 이름입니다. 예를 들어 `quiet-coast`는 `/work/quiet-coast`라는 주소가 됩니다. 상세 페이지 주소를 직접 열거나 새로고침해도 정상 작동해야 합니다.

## 5. 화면별 요구사항

### 5.1 공통 헤더·푸터

- 왼쪽에 텍스트 로고 `Nuvv`, 오른쪽에 `Work`, `About`, `Contact`를 배치합니다.
- Nuvv 로고를 누르면 홈으로 이동합니다.
- 모바일에서는 메뉴가 겹치기 전에 메뉴 버튼으로 전환합니다.
- 모바일 메뉴는 열기·닫기, 바깥 영역 선택, Escape 키로 닫을 수 있어야 합니다. 열린 동안 배경 스크롤을 막고 키보드 초점을 메뉴 안에서 이동시킵니다.
- 푸터에는 작가명, 이메일·인스타그램, 저작권 문구를 표시합니다.
- 관리자 진입은 별도 주소로 제공합니다. 주소를 알고 있어도 인증 없이 편집할 수 없어야 합니다.

### 5.2 Home

**목적:** 첫 화면에서 작가의 분야와 사진 분위기를 전달하고 작업물로 안내합니다.

권장 구성 순서는 다음과 같습니다.

1. **Hero:** 대표 사진 1장, `Nuvv`, 짧은 영문 소개, `View Work` 링크.
2. **Selected Work:** 첫 공개 프로젝트 4개의 대표 사진·제목·카테고리.
3. **About:** 소개 제목, 짧은 본문, 선택적인 프로필 사진.
4. **Contact:** 촬영·협업을 제안할 수 있는 짧은 문구와 연락 링크.

- 대표 사진은 소유자가 고릅니다. 무작위 이미지나 자동 슬라이드는 사용하지 않습니다.
- 사진 위 문구는 명암을 확보하고 얼굴이나 주요 피사체를 가리지 않습니다.
- 모바일에서는 대표 사진과 문구를 따로 배치할 수 있습니다.
- 긴 소개보다 사진이 먼저 보이도록 첫 화면의 문구를 제한합니다.

### 5.3 Work 목록

**목적:** 전체 작업을 한눈에 비교하고 관심 있는 프로젝트로 진입하게 합니다.

- 첫 공개 시 프로젝트 카드 4개를 표시합니다.
- 카드에는 대표 사진, 제목, `Travel` 또는 `Wellness` 분류를 표시합니다. 연도는 실제 정보가 있을 때만 표시합니다.
- 데스크톱은 2열 중심의 편집형 그리드, 모바일은 1열로 구성합니다.
- 사진 비율과 여백을 조정해 매거진 분위기를 만들되 읽는 순서와 탭 이동 순서를 일치시킵니다.
- 카드 전체를 선택할 수 있게 하고 제목은 호버하지 않아도 읽을 수 있어야 합니다.
- 프로젝트 수는 코드에 4개로 고정하지 않습니다. 정보를 추가하면 같은 구조로 목록에 나타나야 합니다.
- 표시 순서는 정보 파일의 `order` 값으로 지정합니다.
- 첫 공개에는 필터나 검색을 넣지 않습니다.

### 5.4 프로젝트 상세

**목적:** 사진의 흐름과 작가의 시선을 충분히 보여줍니다.

상단에는 제목, 카테고리, 1~2문장의 영문 설명을 표시하고 그 아래에 사진을 지정한 순서대로 배치합니다.

- 프로젝트당 사진은 1~10장으로 구성합니다.
- 가로·세로 사진의 원래 비율을 유지합니다. 상세 사진은 기본적으로 잘라내지 않습니다.
- 장소·연도·클라이언트는 제공된 사실만 표시하고 값이 없으면 항목을 숨깁니다.
- 세로 스크롤로 모든 사진을 볼 수 있게 합니다. 자동 재생 갤러리나 가로 스크롤을 필수 탐색 방식으로 사용하지 않습니다.
- 사진을 누르면 확대 화면을 엽니다. 닫기, 이전·다음, `현재 번호 / 전체 장수`를 제공합니다.
- 확대 화면은 모바일 터치 버튼과 데스크톱 키보드 방향키로 이동합니다. Escape로 닫고, 닫으면 처음 누른 사진으로 초점을 돌립니다.
- 확대 화면의 첫 장·마지막 장에서는 존재하지 않는 방향의 버튼을 비활성화합니다.
- 하단에 `Back to Work`와 다음 프로젝트 링크를 제공합니다. 마지막 프로젝트에서는 첫 프로젝트로 이어집니다.
- 사진이 1장인 경우 이전·다음 사진 버튼은 숨깁니다.

### 5.5 About

- 공개 영역에는 제목, 짧은 영문 소개, 전문 분야를 표시합니다.
- 소개 본문은 영문 40~90단어를 권장합니다.
- 소개에서 실제 경력, 수상, 고객사, 거주 지역을 임의로 만들지 않습니다.
- 프로필 사진이 없으면 텍스트만으로 완성된 레이아웃을 제공합니다.
- 관리자가 저장한 내용은 공개 About 영역에 반영됩니다.

### 5.6 Contact

- 이메일 주소는 화면에 보이게 표시하고 `mailto:` 링크로 연결합니다.
- 이메일 복사 버튼을 제공하며 성공 시 `Email copied` 메시지를 잠깐 표시합니다.
- 복사 실패 시 주소를 직접 선택·복사할 수 있도록 안내합니다.
- 인스타그램은 실제 프로필 주소를 연결하고 새 탭으로 열리는 사실을 접근성 이름으로 알립니다.
- 연락처가 없는 상태의 미리보기에서는 준비 중으로 표시할 수 있으나, 실제 공개 전에는 이메일과 인스타그램 주소를 모두 확정합니다.
- 메일 링크는 사용자의 메일 앱을 엽니다. 사이트 자체에서 메시지를 발송하지 않습니다.

## 6. 자기소개 편집과 권한

### 6.1 접근 규칙

관리자는 Nuvv 본인 1명입니다. 일반 방문자는 공개 콘텐츠를 볼 수만 있고 편집할 수 없습니다.

- 공개 회원가입을 제공하지 않습니다.
- 검증된 인증 서비스를 사용하고 소유자의 계정 식별자로 접근을 허용합니다.
- 로그인 화면만 보호하는 방식은 허용하지 않습니다. 서버와 데이터 저장소에서 수정 권한을 매번 검증해야 합니다.
- 비밀키, 로그인 정보, 관리자 비밀번호를 브라우저 코드나 프로젝트 정보 파일에 넣지 않습니다.
- 소개 내용은 서버의 영속 저장소에 저장합니다. 브라우저 저장 공간에만 저장하는 방식은 사용하지 않습니다.
- 저장된 소개는 배포를 다시 하거나 다른 기기로 열어도 유지되어야 합니다.
- 로그인 실패 메시지는 계정 존재 여부를 노출하지 않고, 반복 로그인 시도는 제한합니다.
- 로그아웃하면 보호된 화면에서 더 이상 저장할 수 없어야 합니다.

### 6.2 편집 필드

| 필드 | 형식·제한 | 필수 여부 |
| --- | --- | --- |
| 소개 제목 | 일반 텍스트, 80자 이내 | 필수 |
| 소개 본문 | 줄바꿈 가능한 일반 텍스트, 1,200자 이내 | 필수 |
| 전문 분야 문구 | 일반 텍스트, 120자 이내 | 필수 |

프로필 사진·연락처·프로젝트는 이 편집 화면의 수정 대상에 포함하지 않습니다. 해당 정보는 파일로 관리합니다.

### 6.3 저장 흐름과 상태

1. 로그인한 소유자에게 현재 공개 문구를 불러옵니다.
2. 글자 수와 필수 입력값을 즉시 안내합니다.
3. 미리보기에서 공개 화면과 비슷한 구성을 확인합니다.
4. 저장 중에는 버튼 중복 실행을 막습니다.
5. 저장 성공 시 완료 메시지를 표시하고 공개 화면의 캐시를 갱신합니다.
6. 저장 실패 시 기존 공개 문구를 유지하고 입력 중인 문구도 보존합니다.

- 저장 후 공개 페이지를 새로 열면 10초 안에 수정된 내용이 보여야 합니다. 이미 열린 다른 방문자의 화면은 자동 갱신 대상이 아닙니다.
- 저장하지 않고 나가려고 하면 변경 사항이 사라질 수 있음을 안내합니다.
- 입력값은 일반 텍스트로 처리합니다. HTML이나 스크립트를 입력해도 실행되지 않아야 합니다.

## 7. 작업물 파일 관리

### 7.1 기본 구조

운영자는 하나의 프로젝트 폴더를 복사해 작업을 추가합니다. 코드 파일을 수정하지 않아도 프로젝트 목록이 자동으로 생성되도록 합니다.

```text
portfolio/
├─ prd.md
├─ README.md                 # 제작 시 추가할 실행·수정·배포 안내
├─ content/
│  ├─ site.json              # 작가명, 연락처, 대표 프로젝트 등
│  └─ projects/
│     ├─ quiet-coast/
│     │  ├─ project.json     # 제목, 설명, 사진 순서 등
│     │  └─ images/
│     │     ├─ 01.jpg
│     │     └─ 02.jpg
│     └─ ...
└─ src/                     # 제작 시 추가할 웹사이트 코드
```

위 구조는 구현 기준이며 이 문서 단계에서 웹사이트 코드나 사진 파일이 생성되었다는 뜻은 아닙니다. 관리자 자기소개는 별도의 영속 저장소에서 관리합니다.

### 7.2 프로젝트 정보 예시

아래 값은 형식 설명을 위한 예시입니다. 실제 프로젝트명·장소를 의미하지 않습니다.

```json
{
  "slug": "quiet-coast",
  "title": "Quiet Coast",
  "category": "Travel",
  "summary": "A study of light, distance, and the spaces in between.",
  "order": 1,
  "published": false,
  "cover": "images/01.jpg",
  "coverPosition": "50% 50%",
  "images": [
    {
      "src": "images/01.jpg",
      "alt": "Soft morning light across a quiet shoreline."
    },
    {
      "src": "images/02.jpg",
      "alt": "A narrow path leading toward the sea."
    }
  ]
}
```

- `published`: `true`인 프로젝트만 공개합니다. 미공개 이미지는 배포용 공개 자산에서도 제외해야 합니다.
- `order`: 작은 숫자가 먼저 나타납니다. 같은 값이면 `slug` 순으로 정렬합니다.
- `cover`: 프로젝트 사진 중 대표 이미지를 지정합니다.
- `coverPosition`: 카드에서 잘릴 때 중심 위치를 조정합니다. 상세 사진에는 적용하지 않습니다.
- `images`: 이 배열에 적힌 순서대로 사진을 표시합니다.
- `alt`: 사진을 보지 못하는 방문자에게 내용을 설명하는 문장입니다. 감성 카피와 구분합니다.
- `category`: 첫 버전에서는 `Travel`, `Wellness` 중 하나를 사용합니다.
- 장소·연도·클라이언트가 필요하면 선택 필드로 추가하고, 비어 있으면 화면에서 숨깁니다.

### 7.3 초보자용 추가 절차

1. 예제 프로젝트 폴더를 복사하고 중복되지 않는 영문 폴더명을 정합니다.
2. `images`에 공개할 사진 1~10장을 넣습니다.
3. `project.json`에서 제목, 분류, 설명, 사진 경로·순서·대체 텍스트를 수정합니다.
4. 대표 사진과 표시 순서를 지정합니다.
5. 제공된 검사 명령으로 오류를 확인합니다.
6. 미리보기에서 모바일·데스크톱 화면을 확인합니다.
7. 공개할 때 `published`를 `true`로 바꾸고 배포합니다.

배포는 파일 변경 사항을 실제 방문자가 보는 서버에 반영하는 과정입니다. 파일 수정만으로 운영 중인 사이트가 즉시 바뀌지는 않습니다.

### 7.4 잘못된 파일 방지

검사 명령은 중복된 `slug`, 잘못된 JSON 형식, 필수 필드 누락, 존재하지 않는 사진, 허용하지 않은 분류, 사진 10장 초과를 확인해야 합니다. 오류가 있으면 파일명과 수정할 항목을 안내하고 배포를 중단합니다. 검사 실패로 기존 공개 사이트가 바뀌어서는 안 됩니다.

## 10. 화면 적응과 인터랙션

### 10.1 화면 너비별 동작

| 화면 너비 | 배치 기준 |
| --- | --- |
| 320~767px | 1열, 터치 중심, 메뉴 버튼, 세로 감상 |
| 768~1,023px | 사진·제목 길이에 따라 1~2열, 충분한 터치 여백 |
| 1,024px 이상 | 2열 프로젝트 목록, 넓은 여백과 제목 크기 확장 |

화면 너비에 따라 배치를 바꾸는 반응형 구현을 기본으로 하며, 필요하면 모바일용 대표 이미지 구도를 별도로 지정합니다. 기기 이름만으로 화면을 구분하지 않습니다.

- 320px 너비에서도 의도하지 않은 가로 스크롤이 없어야 합니다.
- 긴 제목, 세로 사진, 모바일 가로 회전에서도 겹침과 잘림이 없어야 합니다.
- 버튼과 링크의 터치 영역은 최소 44×44px을 확보합니다.
- 마우스를 올려야만 중요한 정보가 보이는 구조를 사용하지 않습니다.
- 브라우저 확대 200%에서도 핵심 내용과 탐색 기능을 사용할 수 있어야 합니다.

### 10.2 인터랙션 상세

| 요소 | 동작 | 모바일·접근성 대응 |
| --- | --- | --- |
| 프로젝트 카드 | 호버 시 이미지 약 1.02배 확대, 제목 강조 | 터치로 바로 이동, 키보드 초점 표시 |
| 스크롤 등장 | 짧은 페이드와 소폭 이동, 약 200~400ms | 동작 줄이기 설정 시 제거 |
| 이미지 확대 | 배경을 어둡게 하고 사진 표시 | 닫기 버튼, 초점 관리, 화면 읽기 안내 |
| 페이지 내 이동 | 대상 섹션으로 부드럽게 이동 | 동작 줄이기 설정 시 즉시 이동 |
| 링크·버튼 | 선택 가능 상태를 시각적으로 표시 | 색상 외 밑줄·테두리·초점으로 구분 |

강제 스크롤, 무거운 패럴랙스, 자동 재생 배경 영상, 커스텀 커서는 첫 버전에 포함하지 않습니다. 효과 로딩이 실패해도 사진과 글은 보여야 합니다.

## 11. 품질 요구사항

### 11.1 이미지와 성능

- 원본 사진은 보관하고 배포 시 여러 크기의 웹용 이미지를 생성합니다.
- 가능한 환경에서는 AVIF/WebP를 제공하고 호환 가능한 대체 형식을 둡니다.
- 첫 화면 대표 사진은 우선 로딩하고, 화면 아래 사진은 가까이 스크롤했을 때 불러옵니다.
- 모든 이미지에 크기 또는 비율을 지정해 로딩 중 화면이 튀는 현상을 줄입니다.
- 모바일에서 데스크톱 원본 전체를 내려받지 않도록 화면 크기에 맞는 이미지를 제공합니다.
- 초기 이미지 예산은 모바일 대표 사진 약 300KB, 카드 사진 약 150KB 이하를 목표로 합니다. 화질과 실제 측정 결과에 따라 조정합니다.
- 검색 엔진과 공유 서비스가 제목·설명·대표 이미지를 읽을 수 있는 형태로 페이지를 제공합니다.

**공개 전 성능 목표:** 모바일 조건에서 LCP 2.5초 이하, CLS 0.1 이하를 목표로 검사합니다. LCP는 큰 주요 콘텐츠가 보이는 시간, CLS는 로딩 중 화면 배치가 흔들리는 정도입니다. 배포 후 실제 사용자 데이터가 충분히 모이면 반응 지연 지표인 INP 200ms 이하도 확인합니다. 측정 환경과 실제 결과를 함께 기록하며 초기 점수만으로 실사용 성능을 단정하지 않습니다.

### 11.2 접근성

- 본문 대비는 4.5:1 이상을 확보합니다.
- 사진에 내용을 설명하는 대체 텍스트를 제공합니다. 장식 이미지는 중복 안내하지 않습니다.
- 메뉴, 링크, 확대 화면, 관리자 입력·저장은 키보드로 사용할 수 있어야 합니다.
- 제목 단계, 버튼 이름, 입력 항목 이름을 명확히 구성합니다.
- 모션 감소 설정을 존중합니다.
- 의미 있는 콘텐츠와 연락 수단은 애니메이션 실행 여부에 의존하지 않습니다.

### 11.3 검색·공유

- 홈 제목 예시: `Nuvv — Travel & Wellness Photographer`.
- 상세 페이지는 프로젝트명과 Nuvv를 포함하는 고유 제목·설명을 가집니다.
- 프로젝트 공유 시 해당 대표 사진을 미리보기 이미지로 제공합니다.
- 사이트맵에는 공개 페이지만 포함합니다.
- 관리자 페이지에는 검색 제외 설정을 적용합니다. 이 설정은 접근 권한 보호를 대신하지 않습니다.

### 11.4 이미지 정보와 공개 전 확인

웹용 이미지에서는 불필요한 GPS 위치 등 메타데이터를 제거합니다. 공개할 사진의 사용 권한과 인물·브랜드 공개 가능 여부는 소유자가 확인합니다. 승인되지 않은 사진은 공개 배포에 넣지 않습니다.

- 공개 전 호스팅과 인증·저장소의 요금, 도메인 연결 방법을 소유자가 확인할 수 있게 문서화합니다.

### 13.2 제작 완료 시 납품할 항목

1. 독립된 `portfolio` 프로젝트 전체 소스.
2. 이 PRD와 실행·배포·운영을 설명하는 `README.md`.
3. 프로젝트 추가용 예제 파일과 콘텐츠 검사 명령.
4. 첫 공개 프로젝트 4개의 최종 영문 카피와 사진별 대체 텍스트.
5. 자기소개 편집 화면과 계정 초기 설정 안내.
6. 필요한 환경 변수 이름만 담은 예제 설정 파일. 실제 비밀값은 제외합니다.
7. 모바일·데스크톱 검수 결과와 남은 문제 목록.

## 14. 진행 단계

## 15. 최종 검수 기준

아래 항목을 모두 충족하면 첫 공개 준비가 완료된 것으로 판단합니다.

### 콘텐츠와 탐색

- [ ] 홈에서 Nuvv, Travel & Wellness, 대표 사진, Work 진입 링크가 보인다.
- [ ] 프로젝트 4개가 목록과 각 독립 주소에서 정상적으로 열린다.
- [ ] 프로젝트마다 사진 1~10장이 지정한 순서로 보인다.
- [ ] 실제 사진을 확인한 영문 카피와 대체 텍스트가 들어 있다.
- [ ] 이메일 링크·복사 버튼·인스타그램 링크가 실제 정보로 작동한다.
- [ ] 미정 문구, 예시 고객사, 가짜 연락처가 공개 페이지에 남아 있지 않다.

### 화면과 인터랙션

- [ ] 320, 375, 768, 1,024, 1,440px 너비에서 가로 넘침과 겹침이 없다.
- [ ] iPhone Safari, Android Chrome, 데스크톱 Chrome·Safari·Edge의 검수 시점 안정 버전에서 핵심 흐름을 확인했다.
- [ ] 가로·세로 사진, 긴 프로젝트명, 모바일 회전 상태에서 화면이 유지된다.
- [ ] 확대 보기에서 터치 버튼·키보드·닫기·초점 복귀가 작동한다.
- [ ] 동작 줄이기 설정과 브라우저 200% 확대 상태에서도 탐색할 수 있다.

### 운영과 권한

- [ ] 비로그인 상태와 허용되지 않은 계정으로 소개 수정 요청을 보내면 거부된다.
- [ ] 본인은 로그인 후 소개를 저장하고 공개 페이지에서 변경을 확인할 수 있다.
- [ ] 새 기기 접속과 재배포 후에도 저장한 소개가 유지된다.
- [ ] 저장 실패 시 기존 소개와 입력 중 문구가 보존된다.
- [ ] 예제 폴더 복사와 정보 파일 수정으로 다섯 번째 프로젝트를 추가할 수 있다.
- [ ] 잘못된 사진 경로·중복 주소·사진 10장 초과는 배포 전에 감지된다.
- [ ] `published: false` 프로젝트의 페이지와 사진이 공개 배포에 포함되지 않는다.

### 공개 품질

- [ ] 사진 크기 최적화와 지연 로딩이 작동한다.
- [ ] 모바일 성능 측정 결과와 목표 충족 여부가 기록되어 있다.
- [ ] 프로젝트별 공유 제목·설명·대표 사진이 올바르게 표시된다.
- [ ] 키보드 이동, 사진 설명, 텍스트 대비를 확인했다.

## 16. 공개 전 필요한 자료

아래 항목은 PRD 작성을 막는 사항이 아니라 실제 콘텐츠 완성과 공개 단계에서 채워야 하는 자료입니다.

| 필요한 자료 | 용도 |
| --- | --- |
| 프로젝트별 사진 파일 | 실제 이미지 구성·최적화·영문 카피 작성 |
| 대표 사진과 선호 사진 순서 | 홈·카드·갤러리 구성 |
| 확인된 장소·연도·클라이언트 정보 | 해당 정보가 있을 때만 상세에 표시 |
| 공개 이메일·인스타그램 주소 | 실제 촬영 문의 연결 |
| 관리자 계정 | 본인만 자기소개를 편집하도록 인증 설정 |
| 사용할 도메인·배포 환경 | 사이트 공개와 운영 설정 |

프로필 사진은 선택 사항입니다. 자료가 없으면 생략해도 완성된 화면이 되도록 설계합니다.
