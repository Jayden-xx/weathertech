# Nuvv Portfolio — UI/UX 디자인 가이드

- 기준 문서: `prd.md` v1.0
- 작성일: 2026-10-31
- 버전: 1.0
- 대상: Travel & Wellness Photographer, Nuvv
- 목적: 디자이너와 개발자가 같은 기준으로 공개 사이트와 자기소개 편집 화면을 만들 수 있도록 시각·동작·상태를 정의합니다.
- 적용 범위: Home, Work, Project, 모바일 메뉴, 이미지 확대, 관리자 로그인·자기소개 편집, 오류 화면.

> PRD가 ‘무엇을 만들지’를 정한다면, 이 문서는 ‘어떻게 보이고 반응할지’를 정합니다. 아래 수치는 구현의 기본값입니다. 실제 사진 수령 후 대표 사진의 구도와 잘림 위치를 조정하되, PRD의 기능과 접근성 요구사항은 유지합니다.

## 1. 디자인 방향

### 1.1 콘셉트: Quiet Editorial

**어두운 종이 위에 여행과 휴식의 순간을 편집한 사진 매거진.**

사진은 크게, 설명은 짧게, 여백은 넉넉하게 사용합니다. 따뜻한 아이보리 제목과 낮은 채도의 세이지 포인트로 여행·웰니스의 차분함을 표현합니다. 프로젝트 제목은 항상 보이게 해 방문자가 빠르게 비교할 수 있도록 합니다.

| 원칙 | 실제 적용 |
| --- | --- |
| 사진이 가장 먼저 보인다 | 사진 위 장식·버튼을 최소화하고 본문은 사진 밖에 배치 |
| 감성과 명료함을 함께 유지한다 | 세리프 제목과 읽기 쉬운 산세리프 본문 조합 |
| 중요한 행동이 분명하다 | 핵심 버튼은 화면 영역당 1개, 나머지는 링크나 테두리 버튼 |
| 모바일에서 먼저 성립한다 | 320px에서도 1열로 읽히고 모든 기능을 터치로 사용 |
| 작업이 늘어도 형태가 유지된다 | 카드 구성·정렬 규칙을 반복 적용하고 프로젝트 수를 고정하지 않음 |

기본 테마는 다크 단일 테마입니다. 라이트 테마 전환, 배경 영상, 커스텀 커서, 자동 슬라이드는 첫 버전에 포함하지 않습니다.

## 2. 컬러 시스템

### 2.1 메인·서브·포인트 컬러

`토큰`은 같은 역할의 디자인 값을 반복해서 사용하기 위한 이름입니다. 예를 들어 `--color-accent`를 바꾸면 이 색을 사용하는 버튼과 초점 표시를 함께 바꿀 수 있습니다.

| 역할 | 토큰 | 색상 | 적용 위치 |
| --- | --- | --- | --- |
| 메인 테마: 차콜 | `--color-bg` | `#111111` | 전체 배경, 기본 헤더 |
| 서브: 웜 아이보리 | `--color-text` | `#F2F0EB` | 제목, 본문, 로고 |
| 포인트: 뮤트 세이지 | `--color-accent` | `#B8C4AC` | 핵심 버튼, 키보드 초점, 현재 선택 표시 |
| 표면 | `--color-surface` | `#1B1B1A` | 관리자 입력 영역, 알림, 오류 사진 자리 |
| 높아진 표면 | `--color-surface-hover` | `#252623` | 보조 버튼·입력 영역 호버 |
| 보조 글자 | `--color-text-muted` | `#B5B2AC` | 카테고리, 연도, 안내문 |
| 장식 구분선 | `--color-divider` | `#343434` | 섹션·푸터 구분선 |
| 조작 요소 테두리 | `--color-border-control` | `#777971` | 입력창, 테두리 버튼 |
| 포인트 호버 | `--color-accent-hover` | `#CBD4C2` | 핵심 버튼 호버 |
| 포인트 누름 | `--color-accent-active` | `#A4B497` | 핵심 버튼을 누르는 동안 |
| 오류 | `--color-error` | `#F0A39D` | 입력 오류, 저장 실패 |
| 성공 | `--color-success` | `#B8C4AC` | 복사·저장 성공 문구와 체크 아이콘 |
| 비활성 배경 | `--color-disabled-bg` | `#2D2F2B` | 사용할 수 없는 버튼 |
| 비활성 글자 | `--color-disabled-text` | `#A4A69F` | 비활성 버튼의 라벨 |

사진을 제외한 UI 면적은 차콜 약 80~85%, 표면색 약 10~15%, 포인트색 최대 5%를 방향으로 삼습니다. 아이보리는 주로 글자에 사용합니다. 비율을 맞추기 위해 불필요한 색상 면적을 만들지 않습니다.

### 2.2 조합 규칙과 대비

다음 수치는 지정한 단색끼리 계산한 명암 대비입니다. 사진 위 텍스트나 반투명 요소에는 그대로 적용되지 않습니다.

| 조합 | 계산된 대비 | 용도 |
| --- | --- | --- |
| 아이보리 / 차콜 | 약 16.58:1 | 제목·본문 |
| 보조 글자 / 차콜 | 약 8.93:1 | 부가 설명 |
| 차콜 / 세이지 | 약 10.37:1 | 핵심 버튼 글자 |
| 조작 테두리 / 표면 | 약 3.91:1 | 입력창 경계 |
| 오류 글자 / 표면 | 약 8.56:1 | 오류 안내 |

- 핵심 버튼은 **세이지 배경 + 차콜 글자**로 사용합니다.
- 아이보리 글자를 세이지 버튼 위에 쓰지 않습니다.
- `#343434`는 장식용입니다. 입력창이나 버튼의 유일한 경계로 사용하지 않습니다.
- 정보성 본문은 4.5:1 이상, 조작 요소 경계와 초점 표시는 주변색에 대해 3:1 이상을 확보합니다.
- 오류는 색과 함께 아이콘·문구로 알립니다. 선택 상태도 색만 바꾸지 않고 밑줄이나 테두리를 더합니다.
- 사진 위 제목을 사용하려면 실제 사진에서 대비를 확인합니다. 충분하지 않으면 텍스트를 사진 밖으로 이동합니다.

## 3. 타이포그래피

### 3.1 서체

초기 구현은 외부 폰트를 기다리지 않아도 작동하는 시스템 서체 조합을 사용합니다.

| 용도 | 기본 서체 스택 | 스타일 |
| --- | --- | --- |
| 로고·큰 제목 | `Georgia, "Times New Roman", serif` | Regular 400, 편집 디자인 느낌 |
| 영문 본문·메뉴·버튼 | `Arial, Helvetica, sans-serif` | Regular 400 / Medium에 해당하는 강조 600 |
| 관리자 한글 | `"Malgun Gothic", "Apple SD Gothic Neo", sans-serif` | 본문 400, 라벨·버튼 600 |

웹폰트 도입은 실제 사진을 보며 결정할 수 있습니다. 도입할 경우 사용 권한을 확인하고 최대 2개 계열로 제한합니다. 대체 서체와 글줄 크기가 과도하게 달라지지 않게 조정합니다.

### 3.2 크기 체계

크기는 CSS px 기준입니다. 줄 높이 1.2는 글자 크기의 1.2배를 의미합니다.

| 스타일 | 모바일 320~767px | 태블릿 768~1,023px | 데스크톱 1,024px~ | 줄 높이 / 자간 |
| --- | --- | --- | --- | --- |
| 로고 | 28px | 30px | 32px | 1.1 / -0.03em |
| Hero 제목·작가명 | 52px | 80px | 최대 128px | 1.05 / -0.035em |
| 페이지 H1 | 40px | 64px | 88px | 1.1 / -0.03em |
| 섹션 H2 | 32px | 44px | 56px | 1.15 / -0.025em |
| 프로젝트 카드 제목 | 24px | 28px | 32px | 1.2 / -0.02em |
| About 소개 강조문 | 24px | 28px | 32px | 1.4 / -0.015em |
| 본문 | 16px | 17px | 18px | 1.7 / 0 |
| 메뉴·버튼·폼 | 16px | 16px | 16px | 1.5 / 0 |
| 분류·연도·보조 라벨 | 14px | 14px | 14px | 1.5 / 0.04em |

- 표의 큰 제목 크기는 해당 구간의 기본 목표이며 좁은 공간에서는 유동적으로 줄입니다. 320px에서 Hero 제목의 최소 크기는 44px입니다.
- 본문과 입력 글자는 최소 16px, 부가 정보만 14px을 허용합니다.
- 카드 제목은 줄임표로 숨기지 않고 자연스럽게 줄바꿈합니다.
- 설명 너비는 최대 `60ch`, About 본문은 최대 `52ch`를 권장합니다. `ch`는 글자 수에 가까운 줄 길이 단위입니다.
- 긴 이메일·주소에는 `overflow-wrap: anywhere`를 적용합니다.
- 대문자는 카테고리처럼 짧은 라벨에만 사용하고 본문 전체에는 사용하지 않습니다.
- 페이지마다 H1은 1개를 두고 아래 제목은 H2, H3 순서로 구성합니다.

## 4. 여백·그리드·외곽 형태

### 4.1 여백 단위

기본 단위는 4px입니다. `4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96, 128, 160px` 중에서 선택합니다.

| 위치 | 모바일 | 태블릿 | 데스크톱 |
| --- | --- | --- | --- |
| 화면 좌우 여백 | 20px | 32px | 48px, 1,440px 이상 화면은 80px |
| 섹션 사이 | 80px | 96px | 128px |
| 섹션 제목 → 콘텐츠 | 32px | 40px | 48px |
| 프로젝트 열 사이 | 해당 없음 | 24px | 40px |
| 프로젝트 행 사이 | 48px | 64px | 80px |
| 카드 사진 → 제목 | 16px | 16px | 20px |
| 제목 → 보조 라벨 | 8px | 8px | 8px |
| 폼 필드 사이 | 24px | 24px | 24px |

콘텐츠 영역은 **좌우 여백을 제외하고 최대 1,440px**입니다. 예를 들어 화면 1,440px에서는 좌우 80px을 제외한 1,280px이 콘텐츠 너비입니다. 아주 넓은 화면에서는 최대 너비에 도달한 뒤 중앙 정렬합니다.

### 4.2 그리드

- 모바일: 4개 기준 열, 실제 콘텐츠는 대부분 전체 너비 1열.
- 태블릿: 8개 기준 열, Work는 기본 2열.
- 데스크톱: 12개 기준 열, Work 카드는 각각 6열, About은 제목 4열 + 본문 8열.
- 그리드 자식에는 `min-width: 0`을 적용해 긴 문구가 전체 화면을 밀어내지 않도록 합니다.
- 카드의 시각적 순서와 문서·키보드 순서를 일치시킵니다. CSS로 순서만 뒤집는 구성을 피합니다.

### 4.3 모서리·테두리·그림자

| 요소 | 기본값 |
| --- | --- |
| 사진 | 모서리 0px, 테두리·그림자 없음 |
| 버튼·입력창 | 모서리 2px |
| 알림·관리자 안내 박스 | 모서리 4px |
| 구분선 | 1px, `--color-divider` |
| 조작 요소 경계 | 1px, `--color-border-control` |

큰 둥근 카드, 두꺼운 그림자, 장식용 배지는 사용하지 않습니다. 사진과 텍스트 사이의 여백으로 구분합니다.

## 5. 버튼·링크·아이콘

### 5.1 크기

버튼 높이는 고정 높이가 아닌 **최소 높이**입니다. 문구가 길거나 글자가 확대되면 높이가 늘어나도록 합니다.

| 종류 | 최소 높이 | 최소 너비 | 좌우 패딩 | 사용 위치 |
| --- | --- | --- | --- | --- |
| 핵심 버튼 | 48px | 144px | 24px | View Work, 관리자 저장 |
| 보조 버튼 | 48px | 120px | 20px | 미리보기, 이메일 복사 |
| 작은 버튼 | 44px | 88px | 16px | 로그아웃 등 보조 작업 |
| 아이콘 버튼 | 48px | 48px | 12px | 메뉴 열기·닫기, 사진 이전·다음 |
| 메뉴·텍스트 링크 | 터치 영역 44px | 내용에 따름 | 필요에 따라 8~12px | Work, About, Contact |

- 모바일 Contact와 관리자 주요 행동 버튼은 필요하면 전체 너비로 배치합니다.
- 버튼 안 글자와 아이콘 간격은 8px, 버튼 사이 간격은 최소 12px입니다.
- 핵심 버튼은 같은 영역에 여러 개 나란히 반복하지 않습니다.
- 이동은 링크(`<a>`), 저장·메뉴 열기·복사는 버튼(`<button>`)으로 구현합니다.
- 프로젝트 카드 전체를 하나의 링크로 구성하고 그 안에 다른 버튼을 중첩하지 않습니다.

### 5.2 상태

| 상태 | 핵심 버튼 | 보조 버튼·텍스트 링크 |
| --- | --- | --- |
| 기본 | 세이지 배경 / 차콜 글자 | 보조 버튼: 투명 배경·조작 테두리 / 링크: 아이보리·밑줄 |
| 호버 | `--color-accent-hover` 배경 | 보조 버튼: 표면색 / 링크: 세이지 |
| 누름 | `--color-accent-active` 배경 | 보조 버튼: 높아진 표면 / 링크: 밑줄 유지 |
| 키보드 초점 | 2px 세이지 외곽선, 4px 바깥 간격 | 동일, 기존 스타일 위에 추가 |
| 비활성 | 비활성 배경·글자, 실제 `disabled` 처리 | 비활성 버튼에만 적용, 호버 효과 없음 |
| 처리 중 | 같은 최소 너비 유지, 진행 아이콘 + 상태 문구 | 중복 실행 차단, 보조 기술에 처리 상태 전달 |

진행 중 문구는 공개 화면에서 `Copying…`, 관리자에서 `저장 중…`처럼 동작을 설명합니다. 사진 위 버튼은 불투명 차콜 배경을 사용해 사진 색과 관계없이 식별되도록 합니다.

### 5.3 아이콘

- 기본 크기 20px, 선 두께 1.5~2px, 현재 글자색을 따라가는 단색 아이콘을 사용합니다.
- 확장·이동 화살표, 메뉴, 닫기, 이전·다음, 복사, 성공·오류에만 사용합니다.
- 아이콘 전용 버튼에는 `Close image viewer`, `Next image`처럼 기능을 설명하는 접근성 이름을 붙입니다.
- 외부 링크 표시 화살표만으로 새 탭 정보를 대신하지 않습니다.

## 6. 화면별 레이아웃

### 6.1 공통 헤더

- 모바일 높이 72px, 데스크톱 높이 88px을 최소 기준으로 합니다. 글자 확대 시 늘어날 수 있습니다.
- 차콜 배경으로 상단에 고정되는 sticky 헤더를 사용합니다. 본문 공간을 차지해 콘텐츠를 덮지 않습니다.
- 로고 왼쪽, 메뉴 오른쪽 정렬. 메뉴 사이 간격은 24px입니다.
- 768px 미만에서는 48px 메뉴 버튼을 사용합니다. 글자 확대 등으로 겹칠 경우 더 넓은 화면에서도 메뉴 버튼으로 전환합니다.
- 현재 Work 페이지는 메뉴 아래 1px 밑줄과 `aria-current`로 표시합니다. 홈의 About·Contact는 섹션 이동 링크입니다.
- 앵커 이동 후 제목이 헤더에 가려지지 않도록 실제 헤더 높이 + 24px만큼 스크롤 여백을 둡니다.

### 6.2 Home — Hero

**기본 구성은 ‘문구 블록 → 대표 사진’입니다.** 사진 위 큰 문구를 기본으로 깔지 않아 사진의 원래 분위기와 가독성을 보존합니다.

2. 큰 작가명 `Nuvv`.
3. 한 문장 `Travel, wellness, and the quiet in between.`.
4. `View Work` 링크 버튼.
5. 대표 사진 1장.

- 데스크톱에서는 작가명 왼쪽, 소개·버튼 오른쪽의 2열 문구 블록을 사용할 수 있습니다.

- Hero 전체를 화면 한 장 높이에 강제로 맞추지 않습니다. 320px 화면이나 가로 회전에서도 문구·버튼을 자르지 않습니다.
- 대표 사진에 정보 전달용 텍스트가 포함된 이미지를 사용하지 않습니다.

### 6.3 Home — Selected Work / Work 목록

- 홈은 `Selected Work`, 전체 목록은 `Work` 제목을 사용합니다.
- 홈의 4개 선정 작업 아래에 `View All Work` 링크를 제공합니다. 전체 목록은 공개 작업을 모두 표시합니다.

## 7. 오버레이: 메뉴·이미지 확대

오버레이는 기존 화면 위에 별도로 열리는 영역입니다. 열리면 배경은 조작할 수 없도록 하고, 닫으면 열었던 버튼으로 키보드 초점을 돌립니다.

### 7.1 모바일 메뉴

- 화면 전체를 덮는 불투명 차콜 배경과 72px 이상의 상단 바를 사용합니다.
- 상단은 Nuvv 로고·닫기 버튼, 본문은 32px 메뉴 링크를 16px 간격으로 세로 배치합니다.
- 메뉴 항목을 누르면 메뉴를 닫고 대상 페이지·섹션으로 이동합니다.
- 메뉴 바깥의 여백을 누르거나 Escape 키로 닫을 수 있습니다.
- 메뉴가 열려 있는 동안 배경 스크롤을 막고 초점을 메뉴 안에서 순환시킵니다.
- 가로 회전 시 메뉴 자체는 세로 스크롤할 수 있어야 합니다. 배경은 스크롤되지 않습니다.

### 7.2 이미지 확대 화면

- 배경은 `#0A0A0A`, 상단 도구 영역과 하단 이동 영역을 사진과 분리합니다.
- 상단에는 사진 번호 `01 / 08`과 48px 닫기 버튼을 배치합니다.
- 가운데 사진은 남은 공간 안에서 `object-fit: contain`으로 전체를 보여줍니다.
- 하단에는 48px 이전·다음 버튼을 배치합니다. 모바일에서도 사진을 덮지 않습니다.
- 전체 화면 높이는 동적 뷰포트 높이를 기준으로 하며, 상하단 안전 영역과 브라우저 주소창 변화를 고려합니다.
- 키보드 좌우 방향키로 이동하고 Escape로 닫습니다. Tab 초점은 확대 화면 안에서만 이동합니다.
- 첫 장의 이전, 마지막 장의 다음은 비활성화합니다. 사진이 한 장이면 두 버튼을 숨깁니다.
- 사진 변경 시 현재 번호를 보조 기술에 알리되 초점을 강제로 옮기지 않습니다.
- 확대본을 불러오는 동안 기존 사진을 유지하고 `Loading image…`를 표시합니다. 실패하면 닫기·이동은 계속 사용할 수 있어야 합니다.
- 확대 화면은 큰 보기 기능입니다. 스와이프·핀치 확대·자동 넘김은 첫 버전의 필수 기능에 포함하지 않습니다.

## 8. 관리자 화면

공개 화면과 동일한 색상·버튼을 사용하되, 읽기·입력·오류 수정에 필요한 정보를 분명하게 배치합니다. UI 문구는 한국어입니다.

### 8.1 로그인

- 중앙 정렬된 최대 400px 너비의 폼, 모바일 좌우 20px 여백.
- `Nuvv 관리자`, `본인만 자기소개를 수정할 수 있습니다.` 안내를 표시합니다.
- 실제 로그인 방식이 정해지면 인증 서비스가 요구하는 입력과 로그인 버튼만 제공합니다. 계정 생성·회원가입 버튼은 제공하지 않습니다.
- 입력은 표면색 배경, 조작 테두리, 최소 높이 48px, 16px 글자, 내부 여백 12~16px입니다.
- 실패 시 `로그인 정보를 확인하고 다시 시도해 주세요.`처럼 계정 존재 여부를 드러내지 않는 문구를 폼 상단에 표시합니다.
- 로그인 처리는 서버 권한 검사와 연결해야 합니다. 로그인 화면의 시각적 숨김만으로 권한이 보호된 것으로 간주하지 않습니다.

### 8.2 자기소개 편집

- 전체 최대 너비 1,200px.
- 데스크톱: 입력 6열 + 미리보기 6열, 사이 간격 40px.
- 태블릿·모바일: 입력 → 미리보기 → 저장 순서로 1열 배치합니다. 편집 중 내용은 배치가 바뀌어도 유지합니다.
- 상단에 `자기소개 편집`, 공개 사이트 보기 링크, 로그아웃 버튼을 배치합니다.
- 필드는 소개 제목(80자), 소개 본문(1,200자), 전문 분야(120자) 순서입니다.
- 라벨은 입력창 위 8px 간격, 안내·오류·글자 수는 아래 8px 간격으로 표시합니다.
- 본문 입력창 최소 높이 240px, 세로 크기 조절 허용. 제목·전문 분야는 최소 높이 48px.
- 모든 필드가 필수임을 폼 시작 부분에서 알리고, 플레이스홀더를 라벨 대신 사용하지 않습니다.
- 글자 수는 `240 / 1,200`처럼 표시하고 초과 시 오류 문구를 추가합니다.
- 미리보기에는 실제 공개 화면의 서체·색상·줄바꿈 규칙을 적용하며 `미리보기 — 아직 공개되지 않았습니다`를 표시합니다.
- 저장 버튼은 필수값 누락·길이 초과·변경 없음·처리 중 상태에서 비활성화합니다. 버튼 근처에 비활성 이유를 표시합니다.
- 저장 성공: `저장했습니다. 공개 페이지에 반영됩니다.`를 표시하고 공개 화면 확인 링크를 제공합니다.
- 저장 실패: 폼 위 오류 박스 + 해당 필드 오류를 표시하고 입력 내용을 유지합니다. 일반 서버 오류에만 적용되지 않는 필드 오류를 만들지 않습니다.
- 인증 만료: 재로그인 안내를 표시하고 현재 편집 문구를 화면에 보존합니다.
- 저장하지 않은 변경이 있을 때 내부 이동에는 `계속 편집` / `저장하지 않고 나가기` 확인창을 사용합니다. 브라우저를 닫는 경우는 기본 이탈 경고를 사용합니다.

### 8.3 입력창 상태

| 상태 | 표현 |
| --- | --- |
| 기본 | 표면색 배경, 조작 테두리 1px, 아이보리 입력값 |
| 호버 | 테두리 아이보리 |
| 초점 | 세이지 외곽선 2px, 4px 간격 |
| 오류 | 오류색 테두리 + 오류 아이콘·설명, `aria-invalid` 연결 |
| 읽기 중 | 불러오는 중 문구, 입력·저장 잠시 제한 |
| 비활성 | 비활성 배경과 글자, 이유를 인접 문구로 제공 |

## 9. 인터랙션과 모션

| 동작 | 시간 | 변화 |
| --- | --- | --- |
| 버튼·링크 상태 | 160ms | 색·테두리 변경 |
| 카드 호버 | 300ms | 이미지 1 → 1.02배, 이미지 틀 밖은 숨김 |
| 스크롤 등장 | 320ms | 아래 12px → 원위치, 불투명도 0 → 1 |
| 메뉴 열기·닫기 | 200ms | 불투명도 변경 |
| 확대 화면 열기·닫기 | 200ms | 배경·사진 불투명도 변경 |
| 사진 전환 | 최대 200ms | 짧은 페이드, 슬라이드 이동 없음 |

- 기본 속도 곡선은 `cubic-bezier(0.2, 0.65, 0.3, 1)`입니다.
- 스크롤 등장은 섹션당 최초 1회만 실행합니다. 각 사진을 오래 기다리게 하는 연속 지연은 사용하지 않습니다.
- Hero 대표 사진은 등장 애니메이션을 기다리지 않고 표시합니다.
- hover 효과는 실제 호버가 가능한 기기에서만 실행합니다.
- `prefers-reduced-motion: reduce`에서는 이동·확대·페이드를 제거하고 페이지 내 이동도 즉시 처리합니다.
- 애니메이션 스크립트가 실패하거나 꺼져 있어도 모든 사진·글·링크는 보여야 합니다. 기본 CSS에서 콘텐츠를 영구히 투명하게 두지 않습니다.
- 처리 중 아이콘을 제외한 반복 애니메이션은 사용하지 않습니다. 동작 줄이기에서는 처리 중 상태를 정적인 아이콘·문구로 표시합니다.

## 10. 로딩·오류·빈 상태

| 상황 | 디자인과 문구 |
| --- | --- |
| 사진 로딩 중 | 최종 사진과 같은 비율의 표면색 자리, 번쩍이는 스켈레톤 없음 |
| 사진 로딩 실패 | 자리 크기 유지, `Image unavailable.`, 나머지 사진과 탐색 유지 |
| 프로젝트 없음 | `New work is on the way.` + Contact 링크 |
| 없는 주소 | 큰 `404`, `This page couldn’t be found.`, Back to Work 버튼 |
| 공개 소개 조회 장애 | 마지막 정상 내용 유지, 방문자에게 관리용 기술 정보 노출하지 않음 |
| 관리자 초기 조회 실패 | 오류 박스와 다시 불러오기 버튼, 데이터가 없는데 빈값을 저장하지 못하도록 차단 |
| 저장 실패 | 오류색 아이콘·문구, 다시 저장 버튼, 입력 보존 |
| 복사 실패 | `Copy didn’t work. Select the email address to copy it.` 표시 |

성공 알림은 초점을 빼앗지 않는 상태 영역으로 안내합니다. 반드시 알아야 할 오류는 화면에 유지하고 보조 기술에도 알립니다. 자동으로 사라지는 알림 안에 유일한 복구 버튼을 넣지 않습니다.

## 12. 디자인 검수 체크리스트

### 시각 일관성

- [ ] 차콜·아이보리가 화면을 구성하고 세이지는 핵심 행동에 제한적으로 사용된다.
- [ ] 사진에 일괄 필터·장식 그림자·불필요한 둥근 모서리가 적용되지 않았다.
- [ ] 제목·본문·라벨의 크기와 여백이 정의된 체계를 따른다.
- [ ] 프로젝트명과 분류를 호버 없이 확인할 수 있다.
- [ ] 관리자에 긴 소개를 입력해도 공개 화면의 줄바꿈과 간격이 유지된다.

### 화면 적응

- [ ] 320, 375, 768, 1,024, 1,440px에서 화면 넘침·겹침이 없다.
- [ ] 모바일 가로 회전과 브라우저 200% 확대에서 내용·메뉴·저장 기능을 사용할 수 있다.
- [ ] 긴 이메일·80자 제목·1,200자 소개·세로 사진으로 레이아웃을 확인했다.
- [ ] 프로젝트가 1개·4개·5개일 때 목록과 다음 프로젝트 이동이 자연스럽다.
- [ ] 표지의 중요한 피사체가 모바일·데스크톱에서 잘리지 않는다.

### 조작과 상태

- [ ] 모든 터치 대상이 최소 44×44px이며 버튼 문구가 확대되어도 잘리지 않는다.
- [ ] 키보드 초점이 보이고 메뉴·이미지 확대를 열고 닫은 후 위치가 적절하다.
- [ ] 확대 화면의 번호·처음과 끝 상태·한 장인 경우를 확인했다.
- [ ] 모션 감소 설정에서 이동 효과가 사라지고 콘텐츠가 그대로 보인다.
- [ ] 로딩·성공·실패·비활성·인증 만료 상태를 화면과 문구로 구분할 수 있다.
- [ ] 지정된 단색 대비뿐 아니라 실제 사진 위 조작 요소와 초점 표시도 확인했다.

## 13. 실제 사진 수령 후 확정할 항목

기본 디자인 가이드는 이 문서로 사용합니다. 다음 항목은 사진을 본 뒤 결정하며 현재 임의로 확정하지 않습니다.

1. Hero 대표 사진과 모바일용 크롭 위치.
2. 프로젝트별 표지 사진·카드 크롭 위치·사진 순서.
3. 사진의 분위기에 맞춘 최종 영문 제목·설명·대체 텍스트.
4. 프로필 사진 사용 여부와 실제 공개 이메일·인스타그램 주소.
5. 시스템 서체를 유지할지, 사용 권한이 확인된 웹폰트로 변경할지.

사진 수령 전에도 위 색상·크기·그리드·상태 규칙으로 UI를 설계할 수 있습니다. 실제 사진을 넣은 후 모바일과 데스크톱에서 다시 시각 검수합니다.
