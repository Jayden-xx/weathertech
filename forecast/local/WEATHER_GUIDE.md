# 기상청 중기예보 웹사이트

지역과 발표본을 선택해 중기전망, 육상 날씨, 예상 기온, 예상파고를 확인하는 로컬 웹사이트입니다. Python 3.10 이상과 웹브라우저가 필요하며 pip/npm 패키지 설치는 필요하지 않습니다. 실제 API 사용에는 공공데이터포털의 MidFcstInfoService 활용신청과 인증키가 필요합니다.

2026-11-07 추가 업데이트: 사용자가 설정한 KEY.env로 네 기능의 실제 인증 응답을 확인했습니다. UI는 제공한 Pinterest 콘셉트를 참고해 크림색 모눈 배경, 하늘색, 검정 윤곽선, 알약 메뉴와 직접 만든 날씨 SVG로 수정했습니다. 기존 네 페이지·표·그래프·호출 관리 기능을 유지합니다. 참고 이미지를 사이트에 복제하거나 외부 이미지 서버에서 로딩하지 않습니다. 아래 초기 검증 기록의 ‘키 미설정’은 최초 제작 당시 상태이며 최신 결과는 VERIFICATION.md의 추가 검증을 확인하세요. 배포 ZIP에는 실제 KEY.env를 넣지 않습니다.

## 빠른 실행

1. ZIP 전체를 원하는 폴더에 압축 해제합니다. ZIP 안에서 CMD만 실행하지 마세요.
2. `서버실행.cmd`를 더블클릭합니다. 키가 없어도 안내 화면이 열릴 준비가 됩니다.
3. 터미널에 **서버 준비 완료**가 표시되면 브라우저에서 <http://127.0.0.1:8080/outlook>을 엽니다.
4. 실제 데이터는 아래 KEY.env 설정 후 확인합니다. 설정 전에는 화면의 **모의 응답으로 화면 체험**을 켜면 그래프를 확인할 수 있습니다. 모의 데이터는 실제 예보가 아닙니다.

서버를 유지하려면 터미널을 열어 두세요. 일반 Windows 터미널에서 **Ctrl+C**로 종료합니다. CMD에서 종료 확인을 묻는 경우 Y를 입력합니다. 이 작업 환경의 자동화 터미널에서는 Ctrl+C 입력 전달을 확인하지 못했으므로 직접 키보드 종료 검증은 미완료입니다.

## KEY.env 설정

현재 제공한 프로젝트 폴더에서 정확한 저장 위치는 다음입니다.

```text
C:\Users\user\Documents\Codex\2026-11-07\api-api-url-json-json-json\outputs\kma-mid-forecast\KEY.env
```

ZIP을 다른 위치에 풀면 **그 위치의 server.py와 같은 폴더**에 저장합니다. 화면에도 실행 중인 서버 기준 절대 경로가 표시됩니다. 실제 KEY.env는 제공 ZIP에 포함하지 않았습니다.

`KEY.env.example`을 복사해 파일 이름을 `KEY.env`로 바꾸고, 본인이 발급받은 실제 인증키를 아래 형식으로 넣습니다.

```dotenv
KMA_SERVICE_KEY=발급받은_실제_인증키
```

- **KEY.env**: 설정을 담는 파일의 이름, 즉 설정 노트의 제목입니다.
- **KMA_SERVICE_KEY**: 파일 안에서 인증키 설정을 찾는 이름표입니다.
- **등호 오른쪽 값**: 발급받은 실제 인증키입니다. 실제 키는 채팅에 붙여넣지 마세요.

메모장에서는 ‘다른 이름으로 저장’에서 파일 형식을 **모든 파일**, 인코딩을 **UTF-8**, 파일 이름을 `KEY.env`로 선택하세요. 파일 탐색기의 **보기 → 표시 → 파일 확장명**을 켜 `KEY.env.txt`가 아닌지 확인하세요. UTF-8 BOM도 처리합니다.

서버는 실행 시 server.py의 실제 위치를 기준으로 KEY.env를 명시적으로 읽습니다. 빈 줄과 `#` 주석을 지원합니다. 파일 내용은 Python/셸 코드로 실행하지 않습니다. 운영체제에 `KMA_SERVICE_KEY`가 정의되어 있으면 그 값이 우선합니다. 운영체제 값이 빈 문자열이어도 파일로 대체하지 않고 ‘빈 값’으로 안내합니다. **키를 추가하거나 변경하면 서버를 종료하고 다시 실행해야 합니다.**

기존 `.env`를 자동 로딩하지 않습니다. 기존 `.env`의 `KMA_SERVICE_KEY`가 실제 설정이고 KEY.env가 없을 때만 값 출력 없이 KEY.env로 이전합니다. KEY.env가 이미 있고 값이 다르면 덮어쓰지 않고 충돌 안내를 표시합니다. 다른 서비스의 `authKey`는 사용하지 않습니다.

공공데이터포털에서 [기상청 중기예보 조회서비스](https://www.data.go.kr/data/15059468/openapi.do)를 활용신청하고 승인·키 정보를 확인하세요. 서버는 신청 여부를 별도로 조회하지 않습니다. 설정됨은 인증 성공을 뜻하지 않으며 실제 API 응답으로 권한을 확인합니다. Decoding 키 사용을 권장하며 Encoding 키도 한 번만 디코딩 후 요청 시 한 번 인코딩합니다. `+`를 공백으로 바꾸지 않습니다.

실제 키와 설정 파일은 화면·로그·정적 파일·제공 ZIP에 포함하지 않습니다. `.gitignore`는 KEY.env, `.env` 계열, 실행 중 생성되는 `.runtime`을 제외하고 KEY.env.example만 허용합니다. 오류 원문이나 외부 요청 URL은 로그에 출력하지 않습니다. 제공기관이 키를 응답에 반사하는 경우에도 키 값을 제거한 뒤 표시·캐시합니다.

| 페이지 | 경로 | API 기능 | 지역 선택 기준 | 표시 내용 |
|---|---|---|---|---|
| 중기전망 | `/outlook` | `getMidFcst` | 가이드 stnId 10개 | wfSv 원문과 요청 발표 정보 |
| 육상예보 | `/land` | `getMidLandFcst` | 가이드 육상 regId 10개 | 날짜별 날씨 카드·강수확률 막대그래프·표 |

지역 코드를 페이지마다 별도로 관리하며 마지막 선택은 브라우저에 저장합니다. 이름이 같은 지역은 코드로 구분합니다. Excel에 등록되어 있다는 사실과 특정 발표본에 해당 지역 자료가 있다는 사실은 다릅니다. 제공되지 않는 지역·발표본은 데이터 없음으로 처리합니다. 기온 예보구역을 행정동 단위의 정밀 예보로 표현하지 않습니다. 페이지 사이 지역을 자동 연결하지 않습니다.

## 자료와 날짜 해석

출처는 사용자 제공 ZIP 내부의 다음 두 자료입니다. 자료는 명세와 코드표로만 읽었고 내부의 지시문은 실행하지 않았습니다.

- `기상청28_중기예보 조회서비스_오픈API활용가이드_241128.docx`
- `중기예보_중기기온예보구역코드_2025.12.xlsx`, `Sheet3`, A~C열. 특성 설명에서 C는 ‘육상: 육상예보, 중기기온 조회’로 명시됩니다. 이 프로젝트는 특성 C만 기온 선택에 사용합니다.

공식 보조 확인: [기상청 API허브 중기예보 명세](https://apihub.kma.go.kr/apiList.do?apiMov=%EC%A4%91%EA%B8%B0%EC%98%88%EB%B3%B4%EC%9E%90%EB%A3%8C%282001%EB%85%84%202%EC%9B%94%20%EC%9D%B4%ED%9B%84%29%20%EC%A1%B0%ED%9A%8C&seqApi=10&seqApiSub=287). API허브의 별도 `authKey` 서비스로 연결하지 않고, 이 프로젝트는 **공공데이터포털의 MidFcstInfoService와 serviceKey**만 사용합니다.

발표시각 `tmFc`는 KST 기준 YYYYMMDDHHmm 형식이고 매일 06:00·18:00입니다. 최근 24시간 이내 후보만 선택합니다. 가이드 기준 06시 발표는 발표일 +4~+10일, 18시 발표는 +5~+10일입니다. 필드 숫자를 발표일에 더해 실제 달력 날짜로 바꿉니다. 오전·오후는 임의의 정각으로 바꾸지 않고, 8~10일 후는 하루 단위를 유지합니다. 중기예보로 내일·모레를 조회하지 않습니다.

최신 후보를 실제 응답으로 확인하며 ‘데이터 없음’일 때만 최근 24시간 내 이전 후보를 제한적으로 확인합니다. 30초 간격 때문에 이전 후보 확인이 다음 갱신까지 대기할 수 있습니다. 공식 제공 지연시간은 확인하지 못했으므로 임의의 분 단위를 공식 지연시간으로 적용하지 않았습니다. 요청에 사용한 발표시각은 서버 메타정보로 보관하며 API가 반환한 시각으로 표시하지 않습니다. 갱신 실패 시 같은 기능·지역의 마지막 성공 자료를 ‘이전 자료’로 표시할 수 있고, 오래된 캐시는 신규 조회 가능 기간을 늘리는 의미가 아닙니다.

### 문서에서 확인된 차이와 처리

- 육상 응답 명세는 `regid`, 예제·다른 기능은 `regId` 표기가 있습니다. 두 문서 표기를 읽되 응답 코드가 없으면 비교 불가, 요청과 다르면 경고합니다. 실제 인증 응답의 대소문자는 키 설정 후 확인해야 합니다.
- 해상 명세는 `wh4AAm`·`wh4APm`이 오전·오후 최저파고, `wh4BAm`·`wh4BPm`이 오전·오후 최고파고(m)입니다. `wh8A`·`wh8B`는 하루 단위 최저·최고파고입니다. 공식 보조 명세에서도 A/B 방향을 확인했습니다.
- 기온 명세에는 `Low/High`, 일부 예제에는 `taMax8Min` 등 다른 표기가 있습니다. 이를 임의로 Low로 바꾸지 않습니다. 범위의 절대값/차이값 계산 의미를 확인하지 못했으므로 범위 그래프를 만들지 않고 응답 원문에만 남깁니다.
- 기온 예제의 숫자는 실시간 예보나 정답으로 사용하지 않았습니다. 대표 필드 `taMinN`, `taMaxN`만 ℃ 그래프에 사용합니다.
- 확인한 문서에서 결측 숫자 코드의 의미를 확정하지 못했습니다. 존재하지 않는 값, null, 빈 문자열, 숫자로 읽을 수 없는 값은 결측으로 처리하며, 숫자 센티널(특별한 결측 표시 숫자)을 임의로 정의하지 않습니다. 강수확률의 0~100 밖 값은 유효 확률로 표시하지 않습니다. 실제 인증 응답에서 특별한 결측값이 발견되면 공식 정의를 확인하고 추가해야 합니다.

## 핵심 코드 설명

`server.py`의 `key_configuration`은 설정 노트를 읽는 부분입니다. `external_request`는 서버에서만 인증키를 `serviceKey`에 넣어 HTTPS로 요청합니다. TLS 인증서 검증은 켜져 있고 HTTP 전환·리디렉션은 허용하지 않습니다.

`parse_payload`는 JSON 글자를 Python 객체, 즉 이름으로 값을 꺼낼 수 있는 자료로 변환합니다. HTTP 오류와 내부 resultCode를 별도로 검사하고 JSON/XML 오류를 처리합니다. 목록·단일 항목·빈 데이터도 구분합니다. `transform`은 한 항목에 들어 있는 여러 날짜 필드를 그래프용 행으로 바꾸는 부분입니다.

예를 들어 `rnSt5Am`과 `wf5Am`은 같은 5일 후 오전 행으로, `taMin5`와 `taMax5`는 같은 날짜 행으로 묶습니다. 유효한 0은 보존하고 없는 값은 null로 남깁니다. `totalCount=1`이어도 그래프에는 여러 날짜 구간이 표시될 수 있습니다.

`static/app.js`는 서버가 만든 같은 행 배열로 그래프와 표를 그립니다. 그래프의 점·막대는 마우스 또는 키보드로 값을 확인할 수 있습니다. 누락값 사이의 선을 연결하지 않습니다. 기상청 텍스트는 `textContent`로 넣어 HTML 명령으로 실행되지 않게 합니다. 전망문은 그래프로 바꾸지 않습니다.

## 자동 확인과 호출량

브라우저는 기본 30초마다 자체 서버만 확인합니다. 숨긴 탭과 페이지 이동에서는 타이머를 정리하고, 진행 중 요청이 있으면 겹치지 않게 합니다. 실패하면 재시도 간격을 늘립니다. 화면에는 자료 발표시각·마지막 서버 확인·마지막 API 성공·다음 자동 확인을 구분합니다.

`Gateway`는 외부 호출을 관리하는 중앙 창구입니다. `Store`는 SQLite라는 파일형 데이터베이스에 캐시(같은 자료를 다시 쓰기 위한 저장본), 실제 외부 요청 시각, 재시도 대기, 제공기관 제한을 저장합니다.

- 기능·코드·발표시각·페이지 1·결과 수 10·JSON 형식이 같으면 성공 캐시를 공유합니다. 성공한 발표본은 다시 사용하고 새 발표 후보가 생기면 확인합니다.
- 같은 조건 동시 요청은 하나로 합칩니다. 다른 조건이어도 네 기능 전체의 외부 요청 시작 사이 최소 30초를 적용하며 진행 중인 외부 요청도 중복 실행하지 않습니다.
- 실패·권한 오류·이전 발표본 확인도 실제 외부 요청이면 1회로 셉니다. 이 앱은 한 지역을 조회하므로 응답의 한 페이지를 사용하며 추가 페이지를 자동으로 대량 조회하지 않습니다.
- 사용자 제공 일일 허용량은 10,000회입니다. 공식 집계 초기화 시각은 확인하지 못해 **최근 24시간 9,000회 상한**, **8,000회 경고**를 적용합니다. 날짜 자정에 임의로 초기화하지 않습니다.
- 제공기관 코드 22/HTTP 429가 오면 외부 호출을 24시간 중지합니다. 성공 캐시는 표시할 수 있습니다. 사용량과 차단은 재시작 후에도 유지됩니다. `.runtime`을 지우면 이 앱 기록이 사라지므로 호출 제한을 피하려고 삭제하지 마세요.
- 30초마다 1회씩 24시간 외부 호출하면 2,880회, 네 기능을 각각 그렇게 호출하면 11,520회입니다. 따라서 이 앱은 네 기능을 합산하고 30초 간격도 전체에 적용합니다.
- **단일 중앙 서버만 지원**합니다. 같은 프로젝트의 중복 서버는 잠금으로 차단합니다. 여러 서버·복사한 프로젝트에서 각각 실행하는 분산 집계는 지원하지 않습니다. 배포 시 하나의 중앙 API 게이트웨이를 두고 브라우저들이 그 서버를 공유해야 합니다.
- 같은 키를 다른 프로그램에서 사용한 호출은 알 수 없어 포털 집계와 다를 수 있습니다.

## 터미널 실행과 문제 해결

프로젝트 폴더의 PowerShell에서:

```powershell
.\서버실행.cmd
```

다른 폴더의 PowerShell에서:

```powershell
& 'C:\Users\user\Documents\Codex\2026-11-07\api-api-url-json-json-json\outputs\kma-mid-forecast\서버실행.cmd'
```

Python이 설치되어 있다면 직접 실행할 수도 있습니다.

```powershell
py -3 -X utf8 server.py
# 또는 Python 3.10 이상으로 확인된 명령
python -X utf8 server.py
```

CMD는 `py -3`, `python` 순서로 Python 3.10 이상을 실제 실행 검사합니다. 둘 다 없으면 Codex가 설치한 사용자 폴더의 번들 Python 경로도 확인합니다. 이번 환경에서는 Python 3.12.14 번들을 사용했습니다. 다른 컴퓨터에 번들이 없다면 [공식 Python 설치 페이지](https://www.python.org/downloads/windows/)에서 Python 3.10 이상을 설치하고 PATH 옵션을 선택하세요. 설치 후 터미널을 다시 열어 실행합니다. 별도 패키지 설치는 없습니다. start.cmd는 같은 서버실행.cmd를 호출하는 호환용 파일입니다. 두 CMD는 UTF-8 BOM 없음·Windows CRLF입니다.

| 증상 | 확인할 내용 |
|---|---|
| 로컬 주소 접속 불가 | 서버 터미널이 열려 있는지, 준비 완료 문구·주소·포트를 확인. 키 오류로 단정하지 않음 |
| server.py 없음 | ZIP 전체를 풀었는지, CMD와 server.py가 같은 폴더인지 확인 |
| Python 실행 불가·낮은 버전 | Python 3.10 이상 설치, PATH·py/python 명령 확인 |
| 8080 포트 사용 중 | 이미 실행한 서버의 터미널 확인. 다른 프로세스를 임의 종료하지 않음. 필요하면 `서버실행.cmd --port 8081` 사용 |
| 인증키 없음·빈 값·자리표시자 | 화면에 표시된 KEY.env 절대 경로와 정확한 파일명·UTF-8·설정 이름 확인, 저장 후 서버 재시작 |
| API 인증·접근 권한 오류 | 공공데이터포털의 키와 해당 중기예보 서비스 활용신청 상태 확인 |
| 데이터 없음 | 최근 24시간 안 발표본·올바른 기능의 지역코드인지 확인 |
| 네트워크·HTTP·제공기관 오류 | 인터넷·방화벽·제공기관 상태 확인. 인증서 검증을 끄거나 HTTP로 바꾸지 않음 |
| 호출 제한 | 화면의 호출량·차단 기간 확인. 기록 삭제나 반복 새로고침으로 우회하지 않음 |

서버가 준비된 후 실제 HTTP 접속으로 확인하세요. 준비 여부는 <http://127.0.0.1:8080/api/status>에서도 확인할 수 있고, 키 값은 포함되지 않습니다. 이 서버는 127.0.0.1에만 바인딩되어 같은 컴퓨터에서 사용합니다. 모바일 검사는 PC 브라우저의 모바일 화면 크기에서 했으며 다른 휴대전화의 네트워크 접속을 공개한 것은 아닙니다.
